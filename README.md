# Мессенджер на GitHub Pages + Supabase (бесплатно)

Личные чаты 1-на-1, вход по email и паролю, сообщения приходят мгновенно.
Сайт хранится на GitHub Pages, сообщения и аккаунты в бесплатном тарифе Supabase.
Карта не нужна, всё бесплатно.

Файлы:
- `index.html`: сам мессенджер
- `config.js`: сюда вставить ключи от Supabase
- `schema.sql`: создаёт базу данных (запускается один раз)

---

## Шаг 1. Supabase (база данных)

1. Зайдите на **supabase.com**, нажмите **Start your project** и войдите через GitHub.
2. Нажмите **New project**. Укажите любое имя и придумайте пароль базы (сохраните его где-нибудь).
   Регион выберите **Central EU (Frankfurt)**. Подождите пару минут, пока проект создаётся.
3. Слева откройте **SQL Editor**, затем **New query**. Скопируйте туда **весь** файл `schema.sql`
   и нажмите **Run**. Должно появиться «Success».
4. Слева **Authentication** → **Sign In / Providers** → **Email**. Выключите **Confirm email**
   и сохраните. Тогда регистрация работает сразу, без письма (бесплатная почта Supabase
   отправляет всего несколько писем в час).
5. Слева **Project Settings** → **API** (или **API Keys**). Скопируйте:
   - **Project URL**, вида `https://abcd1234.supabase.co`
   - **Publishable key** (или **anon public** key)

## Шаг 2. Вставить ключи

Откройте `config.js` в любом текстовом редакторе (подойдёт и Блокнот) и замените две строки:

```js
export const SUPABASE_URL = 'https://abcd1234.supabase.co';
export const SUPABASE_KEY = 'sb_publishable_...';
```

Эти ключи публичные, хранить их на GitHub нормально. Чужие сообщения защищены правилами
в базе: каждый видит только свои переписки.

## Шаг 3. GitHub Pages (сайт)

1. На **github.com** нажмите **+** → **New repository**. Назовите, например, `messenger`,
   выберите **Public** и нажмите **Create repository**.
2. На странице репозитория нажмите **uploading an existing file**
   (или **Add file → Upload files**), перетащите `index.html`, `config.js`, `schema.sql`, `README.md`
   и нажмите **Commit changes**.
3. Откройте **Settings** → **Pages**. В **Source** выберите **Deploy from a branch**,
   ветку **main**, папку **/ (root)**, затем **Save**.
4. Через 1–2 минуты там появится адрес вида `https://ВАШ-НИК.github.io/messenger/`.

## Шаг 4. Связать сайт и Supabase

В Supabase откройте **Authentication** → **URL Configuration**, в **Site URL** вставьте адрес
сайта из шага 3.4 и сохраните.

## Готово

Откройте сайт, зарегистрируйтесь (ник, email, пароль). Друг регистрируется так же.
Потом впишите его ник в поиск слева и пишите.

---

## Если что-то не работает

- **«Почти готово, откройте config.js»**: ключи не вставлены или файл не загрузился на GitHub.
- **«Нет связи с сервером»**: неверный URL в `config.js` или Supabase недоступен из вашей сети.
- **Сообщения доходят только после обновления страницы**: проверьте, что `schema.sql`
  выполнился полностью (последняя строка включает мгновенную доставку).
- **После изменения файлов сайт не обновился**: подождите минуту и обновите страницу с Ctrl+F5.

## Ограничения бесплатного тарифа

- Supabase **приостанавливает проект после 7 дней без активности**. Включить его снова
  можно кнопкой **Restore** в панели Supabase, данные не пропадают.
- 500 МБ базы. Для текстовых сообщений это очень много.

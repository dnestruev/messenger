# Лента «События» для создателя — короткий дизайн

**Зачем.** Владелец не хочет сам проверять магазин, админку и узлы: всё важное должно само приходить в одно место.

**Что это.** Строка «События» под «Новостями» в списке чатов. Видит только создатель. Счётчик непрочитанного. Нажал — список записей, новые сверху; нажал на запись — открылось нужное место.

**Что туда падает (решено с владельцем 13.11):**
- новая заявка на лимитку из магазина → «Заявки»;
- новая заявка на Премиум → «Заявки»;
- сделка «с рук» состоялась (для сведения);
- новый узел; узел перестал отвечать / снова заработал;
- новый TURN;
- новый человек зарегистрировался → карточка в админке;
- модератор забанил / разбанил (баны самого создателя не пишем).

**Не входит (v1).** Уведомления на телефон; настройка, какие события показывать; события для модераторов.

**Чего нельзя допустить.** Записи не должны быть видны никому, кроме создателя (в них ники и суммы). Сбой записи события не должен ломать само действие (заявку, регистрацию, бан).

**Подходы.**
1. *Таблица + триггеры в базе* (выбран): `admin_events`, запись делают триггеры на таблицах-источниках; клиент читает и слушает Realtime. Ничего не теряется, даже когда создатель не в сети; клиенты других людей не участвуют.
2. Клиент покупателя сам шлёт событие — отвергнут: можно подделать и можно «забыть».
3. Собирать ленту на лету запросом по всем таблицам — отвергнут: нет «непрочитанного», тяжёлый запрос, нельзя добавить push позже.

**Устройство.**
- `admin_events(id, kind, text, go, created_at)`; RLS: select только создателю; insert/update/delete клиентам закрыт. В публикации Realtime.
- `log_event(kind, text, go)` — security definer, внутри `exception when others then null` (сбой не ломает действие).
- Триггеры: `limited_orders` (insert не-resale; update → approved для resale), `premium_orders` (insert), `nodes` (insert; смена status), `turn_providers` (insert), `profiles` (insert), `bans` (insert/delete, если `by_user` не создатель).
- Чистка: записи старше 60 дней удаляет существующий ночной cron.
- Клиент: `events = {list, off, ch}`; `startEvents()` при входе создателя; строка `eventsRow()`; экран — модальное окно со списком; «прочитано» — последний увиденный id в localStorage; новое событие при открытом приложении — тост.
- `go`: `orders` → `openShop('orders')`, `user:<ник>` → админка с поиском, `nodes` → окно партнёров, пусто → ничего.

**Решения исполнителя (не владельца):** экран — модальное окно, а не отдельный полноэкранный вид; текст события собирается на сервере по-русски; хранение 60 дней.

**Проверка.** `tests/db/t23.sql` (каждый источник даёт запись; чужой не читает; сбой лога не ломает вставку), `tests/app/t_events.py` (строка только у создателя, счётчик, переход в «Заявки», событие прилетает без перезагрузки).

## Жёсткие правила

1. **Изменения в рабочей базе — только после явной фразы владельца «применяй update-N».** Защита сессии блокирует `apply_migration` без неё — не обходи. Сначала пиши `update-N.sql`, тестируй, объясняй, потом проси фразу.
2. **Никаких секретов в репозитории** (он публичный и раздаётся GitHub Pages). В `config.js` — только публичный URL, publishable-ключ и публичный VAPID-ключ. Сервисные ключи, VAPID private, пароли — никогда.
3. **Перед каждой выкладкой — `./scripts/bump.sh`**, иначе у людей смешается старое оформление с новым кодом (было: не появилось окно звонка). Новый JS-модуль — добавь его в список в `bump.sh`.
4. **Проверяй перед выкладкой** (см. «Тесты»). Синтаксис ES-модуля проверять так: скопировать в `*.mjs` и `node --check` (обычный `node --check file.js` проверяет как CommonJS и пропускает ошибки).
5. Коммиты — от имени `dnestruev`, с трейлерами из системных напоминаний (Co-Authored-By / Claude-Session). Пушить в `main` (это и есть выкладка).
6. Чужие картинки/персонажи/наборы стикеров не использовать — только своё (набор «Точка» нарисован с нуля).

## Файлы

- `index.html` — разметка + SVG-спрайт иконок (`<symbol id="i-…">`), ранний скрипт темы.
- `css/styles.css` — всё оформление. Темы через `[data-style]` (classic, dot, paper, neon) × `[data-mode]` (light/dark). Шрифты Inter, JetBrains Mono, Doto (точечный, только латиница/цифры).
- `js/main.js` (~3200 строк) — всё приложение. Хелперы `h()` (создание DOM), `icon()`, `$()`. Состояние `state`, ключи `keys`.
- `js/crypto.js` — WebCrypto: личный ключ ECDH P-256 (неизвлекаемый, в IndexedDB), бэкап под секретным кодом (PBKDF2 600k + AES-GCM), ключи чатов AES-256-GCM, обёртка ключа для каждого участника (ECIES), подписи ECDSA, коды безопасности.
- `js/net.js` — сеть партнёров: зашифрованные куски `chatId/sha256`, по 2 копии на узлы **разных владельцев**, проверка хеша, жалобы на плохие узлы.
- `js/md.js` — markdown (только DOM, без innerHTML), `js/qr.js` — свой генератор QR, `js/stickers.js` — набор «Точка» (SVG), `js/embeds.js` — плееры Spotify / Яндекс Музыка / YouTube / SoundCloud.
- `sw.js` — push, клик по уведомлению, сверка своих файлов с сервером (`cache: no-cache`).
- `config.js` — публичные настройки. Можно добавить `export const ICE_SERVERS = [...]` (TURN для звонков) — код подхватит.
- `partner/` — всё для партнёров: `node.sql`, функция `node` (у каждого партнёра своя копия — **менять её нельзя без их передеплоя**, поэтому новое делаем на стороне клиента/центра), `README.md`.
- `schema.sql`, `update-1.sql … update-12.sql` — база. **Применены все 1–12** (из update-6 убран перенос pg_net — на нём держатся push и пинг узлов; update-12 — время сообщения ставит сервер, удаление своих вложений из хранилища центра, ник не меняется через API).
- `tests/` — стенд проверки (см. `tests/README.md`): SQL-заглушки Supabase + сценарии, Supabase в памяти + Playwright-тесты. На сайт не влияет.
- `scripts/bump.sh` — номер версии перед выкладкой.

## Грабли, на которые уже наступали (не повторяй)

- **Перерисовка ленты** (`renderMessages`) пересоздаёт все пузыри → анимации появления проигрываются заново («прыгает»), прокрутка сбивается, картинки мигают. Поэтому: анимировать только реально новое; точечные обновления (реакции) — патчить один пузырь (`patchReactions`); загруженные `<img>` и открытые плееры переиспользуются через пулы; прокрутка вниз — только при открытии чата, своём сообщении или если и так были внизу.
- **Кеш браузера**: см. правило 3. Плюс SW сверяет файлы с сервером.
- **iPhone**: push только iOS 16.4+ и только если сайт добавлен «На экран Домой» из Safari (iPhone 7 = iOS 15 → push невозможен). Высота экрана берётся из `visualViewport` (`--app-h`). Не использовать API новее Safari 15 без запасного варианта (`requestSubmit`, `randomUUID` уже обёрнуты).
- **MediaRecorder** с нарезкой (`start(250)`) на Safari дублирует фрагменты — писать одним куском.
- **Supabase**: `id` у `messages` — bigint. Подписки postgres_changes на DELETE не фильтруются RLS — не делать `replica identity full` для таблиц с чувствительным.
- **SECURITY DEFINER-функции**: внутри `current_user` = владелец функции, поэтому проверки роли вызывающего (`current_user in ('authenticated','anon')`) работают только в функциях БЕЗ security definer.
- В plpgsql `if x >= case … end then` ломает разбор — оборачивать CASE в скобки.
- Аватарка/профиль: колонка `avatar_path` подтягивается с запасным вариантом, если базы ещё нет (`selectProfiles`).
- Узлы партнёров засыпают у Supabase FREE после 7 дней без активности.
- **Realtime DELETE** приходят ВСЕМ подписчикам и без правил доступа, только с ключом строки (у `messages` — `id`, у `conversation_members` — чат+человек). Не перезагружать список на каждое такое событие (было: любое удаление где угодно → `loadChats` у всех); брать только то, что знаем.
- **`loadChats`** нельзя очищать `state.chats` до загрузки нового списка (было: список на миг пустел и мигал, параллельные вызовы гонялись). Сейчас вызовы склеиваются, новый список подменяется целиком.
- **Лента «уезжала» вверх** при любой перерисовке (сохранение профиля, правка и т.п.), если выше экрана были фото: при переносе готового `<img>` в новый пузырь браузер сам сдвигал прокрутку на высоту фото. Положение ленты запоминать в самом начале `renderMessages`, до работы с пулами.
- **Тормоза.** Новое сообщение — только `appendBubble()` (дорисовать в конец), правка — `replaceBubble()`; `renderMessages()` целиком — лишь при открытии чата и редких событиях (было ~0,35 с зависания на КАЖДОЕ входящее). Рисуется окно последних `RENDER_STEP` = 80 сообщений (`state.shown`), кнопка «Показать более ранние» сначала расширяет окно из памяти; переход по цитате/поиск — через `ensureRendered()`. Даты — только через закешированные `Intl.DateTimeFormat` (toLocale…String каждый раз — медленно). Бесконечные анимации — только `transform`/`opacity` (анимация фона/тени перекрашивает каждый кадр). Presence: перерисовка только если зашёл/вышел кто-то из моих чатов. Замер: `Emulation.setCPUThrottlingRate` 4× + PerformanceObserver longtask.
- **Прочтение** (`conversation_members` UPDATE) приходит на каждое сообщение — только `patchTicks()`, не `renderMessages()`.
- Поля, которые ставит сервер (`created_at` и т.п.), клиент мог подделать при вставке — защищать триггером BEFORE INSERT (сделано в update-12).
- **storage.objects** нельзя удалять SQL-запросом (триггер `protect_objects_delete`) — только через Storage API с правилом delete.
- Звонок: после завершения повторные `offer` ещё летят ~3 с — id завершённых звонков помнить (`endedCalls`), иначе звонит снова.

## Тесты

Стенд лежит в репозитории: **`tests/README.md`** — как поднять PostgreSQL с заглушками и прогнать сценарии, как запустить Supabase в памяти и Playwright-тесты (`t_basic`, `t_calls`, `t_more`, `t_window`, `t_layout`). Новую функцию — добавь в заглушку (`tests/app/server.mjs`) и в тест.
- Обязательно гонять вёрстку на 320×568, 375×667 (iPhone 7), 667×375 и 1440×900 (`t_layout.py`, скриншоты в `/home/claude/test/shots`).
- Учти: «Избранное» всегда первое в списке чатов — в тестах не нажимать «первый чат». Чат искать по `.chat-item-name`, а не по тексту всей строки (в превью группы тоже есть имена).
- Окна `confirm()` в Playwright по умолчанию отменяются — вешай `page.on('dialog', d => d.accept())`.

## Сколько выдержит (оценка, FREE-тариф)

Потолок задаёт центр: ~200 человек онлайн одновременно (Realtime), 500 тыс. вызовов функции push в месяц, 500 МБ базы. Грубо: слабое общение ~800 человек, среднее ~160, активное с фото ~40. Узлы партнёров (1 ГБ каждый) нужны: ~1 на 50 / 10 / 2 человек соответственно. Выше — Pro у центра ($25/мес) или второй центр.

- Демонстрация экрана в звонке (только с компьютера), групповые звонки (до 3–4), переключение аудио→видео посреди звонка.

- Защита от «размножения» партнёров через запасные аккаунты (сейчас 1 человек = N аккаунтов = N×5 подарков Плюса).
- Ускорение правил доступа (советник Supabase `auth_rls_initplan`: `auth.uid()` → `(select auth.uid())`) — актуально при тысячах пользователей.
- Включить «Leaked password protection» в Supabase Auth (настройка в панели; может требовать Pro).
- Чего **нельзя** в веб-приложении: общение без интернета по Bluetooth (нужно нативное приложение), push на iOS < 16.4.
